# tsignal — 단타 신호의 근거를 만드는 파이프라인

"어떤 신호에 진입하고 어떤 신호에 청산할 수 있는가"를 **감이 아니라 통계로** 답하기 위한 프로젝트.

지표를 많이 그리는 게 목적이 아니다. 지표 61종에서 뽑아낸 신호 39개를 같은 잣대로
줄 세우고, **살아남는 신호만 남기는 것**이 목적이다.

```
데이터소스 ──▶ 지표(61) ──▶ 신호(39) ──▶ 검증 ──▶ 리포트
 네이버/토스/CSV     envelope, DEMA,      진입 30    유니버스 풀링       "근거표"
 /합성               Williams %R …        청산 9     초과수익 t 검정
                                                     breadth · OOS
```

## 빠르게 돌려보기

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"

# 실데이터 수집 (네이버 금융 공개 일봉, 인증 불필요)
.venv/bin/python -m tsignal fetch --source naver --code 005930 --interval 1d --count 1200

# 유니버스 24종목 풀링 검증 ← 이게 메인
.venv/bin/python -m tsignal universe --source naver --interval 1d

# 단일 종목 리포트 / 등록된 지표·신호 목록
.venv/bin/python -m tsignal report --source csv --code 005930 --interval 1d
.venv/bin/python -m tsignal catalog

.venv/bin/python -m pytest -q
```

리포트는 `reports/005930_5m.md` 에 마크다운으로 떨어진다.

## 설계 원칙

이 네 가지가 없으면 백테스트 결과는 전부 자기기만이다.

### 1. 미래참조 금지 — 기계로 검사한다

신호는 t봉 종가 확정 후 계산하고, 체결은 **t+1봉 시가**로 잡는다.
`tests/test_no_lookahead.py` 가 두 방향으로 강제한다.

- **동작 검사**: 데이터를 t봉에서 잘라 계산한 값 == 전체 데이터로 계산한 t봉 값
- **정적 검사**: 지표/신호 소스에 음수 `shift` 가 있으면 실패 (주석·문자열은 토크나이저로 제외)

실제로 미래참조 지표를 하나 주입해 두 검사가 모두 잡는 것을 확인했다.

### 2. 비용은 전략의 일부가 아니라 전략 그 자체다

기본값 왕복 **28bp** (수수료 1.5bp×2 + 거래세 15bp + 슬리피지 5bp×2).
5분봉 단타의 회당 기대수익은 대개 10~30bp 규모라, 비용을 빼는 순간 대부분의
"잘 되는 신호"가 사라진다. 그래서 비용 차감 후 숫자만 리포트에 싣는다.

### 3. 신호 39개를 동시에 시험하면 t=2 는 문턱이 아니다

엣지가 전혀 없어도 39개 중 두어 개는 t>2 가 나온다. Šidák 보정으로
문턱을 **|t| ≥ 3.1~3.2** 로 올리고, 그 위에 OOS 재현까지 요구한다.

### 3-1. **원시 수익률이 아니라 초과수익을 검정한다**

실데이터를 넣고 나서 발견한 가장 중요한 함정이다.
보유기간을 늘리면 어떤 신호든 t가 커진다 — 시장이 우상향하면
"아무 때나 사서 들고 있기"의 기대값이 양수이기 때문이다.

실제 24종목·5년 일봉에서 보유 20일 기준:

| 신호 | 원시 t | 초과수익 t | 판정 |
| --- | --- | --- | --- |
| `donchian_breakout` | 6.24 | **1.35** | 기각 |
| `cmf_turn_positive` | 6.24 | **2.02** | 보류 |
| `bollinger_lower_reclaim` | 5.13 | **1.40** | 보류 |

원시 t로 판정하면 셋 다 "채택후보"다. 종목별 무조건부 평균을 뺀
**초과수익(edge)** 의 t로 보면 하나도 문턱을 못 넘는다.
그 격차가 곧 '시장이 벌어준 몫'이다.

### 3-2. 한 종목이 아니라 유니버스로, breadth까지

풀링 기대값이 유의해도 24종목 중 3종목이 다 벌어준 것일 수 있다.
`breadth`(종목별 초과수익이 양(+)인 비율)가 0.6 미만이면 `쏠림주의`로 따로 뺀다.

관문을 **모두** 통과해야 `채택후보`:
표본 100회 이상 → 보정된 t_edge 문턱 통과 → breadth ≥ 0.6 → IS/OOS 부호 일치.

### 4. 검증 코드가 없는 엣지를 만들어내지 않는지 검사한다

합성 랜덤워크를 넣었을 때 채택후보가 하나라도 나오면 파이프라인이 고장난 것이다.
`test_random_walk_produces_no_significant_edge` 가 이걸 회귀 테스트로 고정한다.
(실제로 합성 데이터 리포트의 결론은 "채택후보 없음"이다 — 정상이다.)

## 구조

| 모듈 | 역할 |
| --- | --- |
| `ohlcv.py` | 모든 소스가 수렴하는 데이터 계약 (tz-aware KST, 정합성 검사) |
| `datasource/` | `naver`(실데이터) / `toss` / `csv` / `synthetic`. 인터페이스 하나만 만족하면 교체 가능 |
| `indicators/` | 추세 26 · 모멘텀 13 · 변동성 10 · 거래량 12 = **61종 → 피처 102개** |
| `signals/` | 진입 30 · 청산 9. 각 신호에 **검증 대상 가설(rationale)** 이 붙어 있다 |
| `evaluation/` | 이벤트 스터디 · 거래 시뮬 · **유니버스 풀링** · OOS 분할 · 다중검정 보정 · 리포트 |

지표 추가 = 함수 하나 + `register()` 한 줄. 그러면 피처 행렬에도 리포트에도 자동 반영된다.

## 리포트가 답하는 것

1. **진입 신호 스크리닝** — 신호별 기대값 / 무조건부 대비 초과분(edge) / t / IS·OOS / 판정
2. **구간 안정성** — 5등분 구간마다 부호가 유지되는가 (한 구간이 다 벌어준 건 아닌가)
3. **청산 규칙 비교** — 같은 진입에 청산 규칙만 갈아끼웠을 때 순손익이 어떻게 달라지는가
4. **익절/손절 폭 근거** — MFE/MAE 분포 분위수 (%와 ATR 배수 양쪽으로)
5. **청산 사유 분해** — 손절/익절/청산신호/시간/당일청산 각각의 기여

## 토스 API 실측 상태

토스증권은 **공개 문서화된 REST API가 없다.** 내부 엔드포인트를 직접 확인한 결과:

| 엔드포인트 | 상태 |
| --- | --- |
| `GET /api/v2/stock-infos/{A코드}` | ✅ 익명 호출 동작 (종목 메타) |
| `GET /api/v2/stock-prices/{A코드}` | ✅ 익명 호출 동작 (현재가 스냅샷) |
| `GET /api/v1/c-chart/kr-stock/{A코드}/{period}` | ⚠️ 라우트는 존재하나 400 (과거 캔들) |

캔들 경로는 존재하지 않는 경로(404)와 달리 **400**을 준다 — 라우트는 맞고
인증/필수 파라미터가 빠진 상태다. period 후보와 파라미터 후보를 조합 검증했으나
전부 400이었고, 브라우저 세션 헤더가 필요할 가능성이 높다.

그래서 어댑터는 (1) 검증된 엔드포인트를 제공하고, (2) 헤더/쿠키 주입 구멍을 열어두고,
(3) 파라미터 재탐색 도구를 함께 둔다:

```bash
# 브라우저 개발자도구 > Network 에서 c-chart 요청 헤더를 JSON 으로 저장 후
.venv/bin/python -m tsignal probe-toss --code 005930 --headers headers.json
```

자세한 내용은 [`docs/toss-api.md`](docs/toss-api.md).

> 비공식 엔드포인트다. 서비스 약관을 확인하고 본인 책임으로 사용하되,
> 호출 간격(`min_interval_sec`)을 지킬 것. 상용 배포나 대량 수집이 목적이라면
> 한국투자증권 Open API 같은 **공식 채널**을 권한다 — 어댑터만 하나 더 쓰면 된다.

## 실데이터 검증 결과 (24종목 · 5년 일봉)

삼성전자·SK하이닉스 등 코스피 대형주 24종목, 2021-10 ~ 2026-08, 총 28,720봉.

**단일 신호로 보정 문턱을 넘은 신호는 하나도 없다.**

가장 근접한 것은 `rsi_oversold_turn`(RSI 30 이탈 후 회복):
보유 3일 기준 edge +0.71%, breadth 0.79(24종목 중 19종목에서 양수), t_edge 2.80.
문턱 3.11에는 못 미친다. 그리고 IS/OOS로 자르면 t_edge가 2.42 → 0.00 으로 무너진다.

이게 실망스러운 결과처럼 보이지만, 사실은 이 프로젝트가 제대로 작동한다는 증거다.
교과서에 나오는 단일 지표 신호가 비용과 다중검정과 OOS를 통과할 만큼 강했다면
이미 아무도 못 벌고 있을 것이다. **리포트가 "채택후보 없음"을 정직하게 뱉는 것**이
이 도구의 값어치다.

전체 결과는 `reports/universe_1d.md` (직접 생성).

이벤트 스터디 · 거래 시뮬 · 유니버스 풀링 검증 · OOS 검증 · 리포트 생성 ·

**정해야 할 것** — 이야기 나누고 진행하죠:

1. **분봉 조달** — 단타의 본 무대는 1/3/5분봉인데 아직 못 구했다.
   (a) 브라우저 헤더로 토스 뚫기, (b) 한국투자증권 Open API 어댑터,
   (c) 유료 벤더. 추천은 **(b)** — 재현 가능성이 데이터 출처에 걸려 있다.
2. **신호 결합** — 지금은 단일 신호만 잰다. 실제로 돈이 되는 건
   "추세 필터 + 트리거 + 거래량 확인" 조합일 가능성이 높다.
   다만 조합 탐색 = 과최적화이므로, 조합 수만큼 문턱을 더 올려야 한다.
3. **유니버스 확대** — 24종목은 작다. 코스피200 전체 + 상장폐지 종목까지 넣어야
   생존 편향이 빠진다.
4. **숏 사이드** — 현재 롱 전용. 공매도 제약을 감안하면 실익이 있는지.
